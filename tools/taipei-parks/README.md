# 台北市大型公園綠地（專案代號 `taipeiparks`）

這個資料夾是「台北市大型公園綠地」專案的反應區與現場問卷的產生方式與成品，留著是為了日後能說清楚每一區的邊界從哪裡來、為什麼收或不收。網頁不會讀這裡的任何檔案；專案資料存在 Netlify Blobs，由 `seed.mjs` 寫入。

## 反應區怎麼來的

邊界取自 OpenStreetMap，經 Overture Maps `2026-09-23.1` 版的 `base/land_use` 取得（`fetch_overture.py`，公開 S3、免帳號），臺北市界用同版的 `divisions/division_area`（臺北市，約 269.8 km²）。收錄規則寫在 `build_zones.py`：OSM 標為 `leisure=park`，或 `leisure=garden` 且 `garden:type=public` 的多邊形，有名稱、落在臺北市界內的面積達 1 公頃、且一半以上在市界內者。同名且相距 24 m 內的多塊視為同一座公園，以閉合運算（12 m，不成再試 16 m）把窄路切開的部分併成一區；仍分離的就各成一區、名稱相同（大佳河濱公園、文德三號公園各兩區）。八成以上面積落在另一座公園內的子區剔除（關渡自然公園西南賞鳥廣場）。反應區只收單一多邊形的外環，公園內的建物挖洞一律視為區內。頂點以 TWD97 座標簡化，容許誤差 1.5 m。結果是 178 座公園、180 區，清單見 `zones_list.csv`（含每區的 OSM ID）。

命名有四處人工判斷：OSM「圓山公園」與相鄰的無名多邊形合為「花博公園圓山園區」（兩塊都含花博公園、中山親子館等地點），「恆光國小預定地」改名「木柵運動公園」（多邊形內即該公園的地點），北投區一塊無名多邊形依其內信度 0.88 的地點命名為「磺溪河堤環狀公園」，兩座同在北投區的「七星公園」以里別區分為（中心里）與（湖田里）。

刻意不收的有：陽明山國家公園及其各分區（4,800 多公頃，涵蓋住宅與道路，且會與陽明公園、前山公園等重疊造成重複觸發）、臺北市立動物園、台北市野雁保護區與淡水河口保護區（多為水域、灘地，並與河濱公園重疊）、墓地、高爾夫球場、露營場、文化或體育園區（臺北科學藝術園區、故宮、臺北體育園區、松山文創園區）、敦化北路苗圃（公園處苗圃），以及無法可靠命名的無名多邊形：`w963940039`（大同區，實為街廓）、`w423053803`（士林區）、`r4730990`（中山區，美堤河濱旁）、`w548527807`（文山區動物園站前，地點標「動物保育公園」但信度僅 0.69）、`w1553115880`（內湖區週美里）。OSM 標為公園的廣場類（台北市民廣場、台北世貿廣場、中山堂廣場、蔣渭水先生紀念廣場）與臺北流行音樂中心南、北基地依規則收入，研究上不需要可在反應區頁直接刪除。

## 現場問卷

`make_survey.mjs` 產生 `survey.json`，觸發方式為「範圍」，每區每場次跳一次（`repeatMinutes` 0）。前 11 題是 PRS-11（Pasini, Berto, Brondino, Hall & Ortner, 2014, *Procedia – Social and Behavioral Sciences* 159, 293–297），0「完全不符合」到 10「完全符合」，題意採就地作答的 places like this；id 依向度為 `prs_fa*`（迷人性）、`prs_ba*`（遠離性）、`prs_co*`（一致性）、`prs_sc*`（延展性）。後 10 題是 PSS-10（Cohen & Williamson, 1988），參照期間維持原量表的「最近一個月」，0「從不」到 4「非常常」；反向題 id 以 `r` 結尾（`pss04r`、`pss05r`、`pss07r`、`pss08r`），計分時 4 減原值。PSS 做成單選而不是量尺，因為問卷頁的量尺範圍會統一套用到全部量尺題，做成量尺的話，日後在網頁上按一次儲存就會被改成 0–10。中文為工作譯文，正式收案前請以研究室採用的官方中文版逐題覆核。入組問卷未設定。

## 寫入平台

`node seed.mjs` 依序寫入反應區、問卷，最後才登記專案（登記後手機端立刻可選，先登記會讓手機抓到空的範圍），寫完回讀核對。專案代號已存在、或後端已有同代號的範圍或問卷時會停止，不覆蓋任何資料。

不方便從命令列連到站台時，`node make_seed_html.mjs` 產生自含的 `seed.html`，在自己的瀏覽器開啟、按一下即可，流程與保護相同。這一頁對站台是跨來源請求，POST 一律送 `text/plain`：`zones.mjs` 與 `survey.mjs` 的 OPTIONS 預檢回應寫成 `new Response("", { status: 204 })`，在 Node 會拋錯（204 不得帶 body），送 `application/json` 會卡在預檢。
